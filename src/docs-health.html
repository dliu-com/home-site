How dliu.com is tested

Every 15 minutes, status.dliu.com visits dliu.com like an ordinary visitor, without signing in, and checks that each part of the site answers correctly. Nothing is changed by the checks.

What is checked

Pages

The home page, the docs and the page styling open normally. Down means visitors see an error instead of dliu.com.

Health endpoint

None. dliu.com is just files, with no server or database to ask, so the checks above cover the whole site.

Technical details

GET https://dliu.com/health returns 404 with the HTML 404 page; that is expected. Checks send no cookies, no Authorization header and no query string, don't follow redirects, and use the user agent dliu-status-bot/1.0 (+https://status.dliu.com/docs). A check passes when the status matches, the Content-Type starts with the expected type and the body contains the marker (for a redirect, the Location header starts with it).

Caching: HTML has no Cache-Control header (up to 1 day at CloudFront); style.css, resume.pdf and health.md send public, max-age=300, s-maxage=86400, stale-while-revalidate=86400. Every deploy invalidates /*.

What isn't tested

  • Nothing on dliu.com needs signing in, so no signed-in actions are left out.
  • Publishing updates to the site, which the owner does from his own computer.
  • The visitor statistics on traffic.dliu.com; the checker's own visits are left out of them.
